# AEOLIA Local Translator 0.3.2 高精度モード

## 今回の変更
- モデルは従来と同じ Qwen3-4B-Instruct-2507 Q4_K_M。モデルを小さくしたり、さらに量子化したりしていません。
- CPU用の重み再配置を無効化して、翻訳中の追加メモリを削減します。バッチサイズは従来のままです。
- 翻訳がない状態が60秒続くとモデルをメモリから解放します。次の翻訳要求で自動復帰します。復帰後の最初の翻訳には再読込み時間が加わります。
- 文脈長4096・入力上限2500文字・生成上限・翻訳プロンプト・出力チェックは維持しています。モデルが同じでも数値計算の違いによって訳文が変わることはあります。完全な誤訳検出はできません。
- GUIを表示しない起動方法を追加しました。軽量版の操作・モデルは変更していません。

## 更新
ダウンロード済みの本体フォルダーはそのまま使用します。モデルやコア部品の再ダウンロードは不要です。
1. 軽量版・高精度版を閉じます。GUIなしで起動した場合は、通知領域のAEOLIAアイコンを右クリックし「翻訳APIを終了」を選びます。
2. software 0.3.2のZIPを本体フォルダー内に展開します。
3. Update-software-0.3.2内のInstall.cmdを実行します。
4. 完了後にいつもの起動ファイルを使います。旧ファイルは.component-backupsに保存されます。

会社の持込み・実行ルールに従ってください。ブロックされた場合はIT部門に確認し、制限を回避しないでください。

## GUIを使わない場合
本体直下のStart-Quality-API.cmdを実行します。翻訳ウィンドウや選択文字取得用ホットキーは作りません。通知領域のアイコンから終了できます。翻訳前はモデルを読み込まないため、待機中の大きなメモリ確保はありません。

APIはhttp://127.0.0.1:51233の既存インターフェースです。従来のAHK関数AeoliaTranslateは変更不要です。
GUI版とAPI版は同じLauncherを使うため二重起動しません。切替える場合は先に終了してください。GUI版を使用中に呼んだ場合はそのAPIを利用するため、GUIを閉じるとAPIも終了します。
Windows起動時の自動起動登録や、既存のAHKホットキー・クリップボード設定の書換えは行いません。

## 既存のAHK v2へ組込み
ui_quality\AeoliaLocal.ahkを#Includeするか、同ファイルの関数を自作スクリプトに追加します。

```autohotkey
#Requires AutoHotkey v2.0
#Include C:\Apps\AEOLIA\ui_quality\AeoliaLocal.ahk

; 初回または必要時に呼ぶ。本体フォルダーを指定。
AeoliaStart("C:\Apps\AEOLIA")
; 既存APIと同じ。原文を渡して訳文を受け取る。
translated := AeoliaTranslate("Please send the document tomorrow.", "en", "ja")
```

AeoliaStartは起動済みなら再起動しません。繰返し呼んでもモデルの休止タイマーは延長しません。
AeoliaTranslate(text, source := "auto", target := "auto", port := 51233)は同期関数です。source/targetはauto、ja、en。休止からの復帰も自動です。
いずれもホットキー登録や貼付けは行いません。失敗時は例外になり訳文を返さないため、既存スクリプト側では成功後だけ置換し、例外時は原文を残してください。会社の既存AHKスクリプトそのものは未検証です。

## 休止時間の設定
通常は設定不要です。変更したいときだけ、本体直下にconfigフォルダーを作り、その中にquality-settings.jsonをUTF-8で保存します。

```json
{"idle_seconds": 60}
```

1～86400は未使用秒数、0はモデルを解放しない常駐優先です。変更後は翻訳APIを終了して再起動してください。このファイルは更新で上書きしません。書式や値が不正なら起動を止めます。
休止は翻訳処理中には行いません。今後のライブ翻訳の実装は今回の対象外ですが、常駐優先への切替えは可能です。

## 通信と制約
翻訳先はPC内のループバックのみです。クラウドへの自動切替え、翻訳内容のログ、プロキシ利用、HTTPリダイレクトはありません。高精度コアがなければエラーにし、別の翻訳モデルへ自動変更しません。
長い文章は分割してください。数字・一部の識別子の変化や途中打切りはエラーにしますが、意味や否定の誤訳をすべて検出できるわけではありません。

更新・設定・識別子・HTTP・翻訳APIの回帰試験、AHK構文、GUIなし起動・二重起動防止・60秒未使用後の解放・自動復帰・終了を手元PCで確認しました。0.2.0および0.3.1からの更新でコア・設定を維持しています。会社PCのメモリ削減量や速度、会社の既存AHKスクリプトは未確認です。4例で従来設定と比較しましたが、すべての文章で同じ品質・速度を保証するものではありません。
