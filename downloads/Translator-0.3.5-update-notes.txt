AEOLIA Translator software 0.3.5 更新手順
========================================

対象：既存の AEOLIA Translator 0.3.3 / 0.3.4 のソフトウェア更新。
高品質翻訳には導入済みの quality-core が必要です。モデル・Python・llama.cpp の再取得は不要です。
今回の仕様変更は高品質モード（ui_quality、ポート51233）です。軽量モードの仕様は変更していません。

変更内容
--------
数字・識別子の表記や出現回数に差があっても、生成した訳文を通常の成功結果として返します。
numbers_changed / identifiers_changed を理由とする HTTP 422 では停止しません。
例：PLEASE SEND THE DOCUMENT. の大文字一般語や、1 million → 100万の表記変化でも結果を使えます。
再翻訳・自動再試行はしません。GUIは訳文を表示し、差があればステータス欄で軽く注意します。
Ctrl+T側が戻り値を貼り付ける実装なら、差異のある訳文も通常の置換へ進みます。

実際の数字・識別子の欠落や誤変更も返る仕様です。翻訳の正確性を保証するものではありません。
注意がなくても、単位（例：mmとcm）、否定、条件、意味の誤訳や省略はあり得ます。
照合は表記と回数の参考情報であり、注意が出たことも誤訳とは限りません。
空出力、思考タグを含む出力、モデルが途中終了を報告した出力は引き続き422で停止します。
通信・モデル障害や文字数超過等もエラーのままです。例外時は原文を残してください。

更新前
------
1. 作業中の文書を保存し、既存のインストールフォルダーと独自AHKを別の場所へバックアップします。
2. 軽量Translatorを終了し、高品質モードはトレイの「終了（翻訳APIも停止）」で終了します。
   GUIの×は隠すだけで終了ではありません。
3. 自動起動を行う独自AHKも通常の方法で終了し、更新中にAPIを再起動させないようにします。
   会社のプロキシ・管理設定・セキュリティ設定を変更する必要はありません。

更新
----
4. AEOLIA-Translator-software-0.3.5-installer.zip を既存フォルダーの中へ展開します。
   次の配置になるようにしてください。

   AEOLIAフォルダー\runtime\python.exe
   AEOLIAフォルダー\Update-software-0.3.5\Install.cmd

5. Update-software-0.3.5\Install.cmd を実行し、Update completed. を確認します。
   更新器はサイズ・SHA-256・版を検証します。ユーザーが変更した既存ファイルは強制上書きしません。
   エラー時は表示内容とバックアップを残して停止してください。ロックやバックアップを消して強行しないでください。
6. 既存フォルダーの Start-Quality.cmd を起動し、トレイからGUIを表示して版0.3.5を確認します。
   Please send the document. など非機密の短文で試してください。
7. 独自AHKの参照先を確認して再読み込みします。

旧helperの混在について
----------------------
高品質は ui_quality\AeoliaLocal.ahk とポート51233です。軽量の ui\AeoliaLocal.ahk / 51231 と混同しないでください。
AeoliaTranslate(txt, "auto", "auto", 51233) の引数と文字列の戻り値は変わりません。
旧0.3.3/0.3.4 helperの翻訳呼出しでも新APIの結果を受け取れますが、新しい注意表示はありません。
新helperは AeoliaTranslationWarning() で注意コードを取得できます。helper自体は自動コピーしません。
一方、AeoliaStartは版を厳密に確認するため、旧helperと新APIの混在で起動確認に失敗する場合があります。
起動するフォルダーと #Include 先を同じ0.3.5一式に揃え、AHKを再読み込みしてください。
関数をコピーしている場合は helper全体を揃え、重複定義を避けてください。ファイル更新だけでは起動済みAHKは変わりません。
版チェックを削除して回避したり、別フォルダーのAPIを同時起動したりしないでください。

置換と試験範囲
--------------
SafeReplace.ahk は成功時に適用コールバックを呼び、例外時には呼びません。
数字・識別子の差異は今回から成功なので適用されます。待機中に対象入力が変わった場合の確認も必要です。
ReplacementExample.ahk は自身の編集欄だけを置換する任意の例で、Ctrl+T登録や外部アプリへのキー送信は行いません。
会社PCの独自AHK / Ctrl+Tと、そのフォーカス・選択範囲・例外処理は未検証です。
検証は合成入力による実AutoHotkeyの呼出し、GUIコールバック、標準置換呼出側で行っています。
Qwen3実モデルの通常文・技術識別子・数値表記・1,016文字も確認しました。
このPCでは1,016文字の生成約30.66秒、検査約0.45ミリ秒でした。会社PCの速度は保証しません。
今回の変更は主に「生成後に照合で結果が使えなくなる」問題を解消し、モデル生成自体を高速化するものではありません。

設定・復旧
----------
config\quality-settings.json は上書きしません。新規設定のidle_seconds=0、既存の明示的な60秒等は保持します。
Start-Quality.cmdはトレイ常駐で、手動休止後は次の翻訳で再ロードします。
旧ファイルは .component-backups に保持されます。更新器は旧版への上書きダウングレードを拒否します。
問題時は停止して更新前のフォルダーバックアップを保全し、稼働中フォルダーへ一部だけ戻さないでください。
更新器はネットから取得せず、原文・訳文をログ保存しません。ハッシュは破損検知用で、配布元の真正性保証とは異なります。
